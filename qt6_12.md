# Qt 6.12.0 toolchain and porting guide

This document records how Cullendula was moved from Qt 6.11.2 to Qt 6.12.0 and
how to recreate the verified Qt 6.12.0 development environment. It is intended
to make the same process reusable for a clean workstation, CI maintenance, or a
future Qt minor-version update.

## Upstream release and package locations

Qt announced Qt 6.12.0 on September 30, 2026. At the time of this migration,
6.12.0 was the newest stable release in the Qt 6.12 series.

- Release announcement: <https://www.qt.io/blog/qt-6.12-released>
- Stable release index: <https://download.qt.io/official_releases/qt/6.12/>
- Qt 6.12.0 source packages: <https://download.qt.io/official_releases/qt/6.12/6.12.0/>
- Linux binary repository: <https://download.qt.io/online/qtsdkrepository/linux_x64/desktop/qt6_6120/qt6_6120/>
- Windows binary repository: <https://download.qt.io/online/qtsdkrepository/windows_x86/desktop/qt6_6120/qt6_6120_msvc2022_64/>

The download service may redirect an archive request to an official mirror,
such as `ftp.fau.de`. That redirect is expected; the package metadata and
checksums still originate from Qt's repository.

## Required Qt components

Cullendula installs more than the libraries named directly in
`find_package()`, because build tools and observable image-format support also
have runtime dependencies.

| Component | Why it is required |
| --- | --- |
| `qtbase` | Qt Core, GUI, Widgets, Test, platform plugins, and the base development files |
| `qttools` | LinguistTools and `lrelease` for compiling translations |
| `qtdeclarative` | `lrelease` links against Qt QML even though Cullendula contains no QML |
| `qtsvg` | SVG image support exposed by the Extensions menu |
| `qtimageformats` | Additional readers including WebP and TIFF |
| `qttranslations` | Qt's own translation resources used by packaged applications |
| `icu` | Runtime libraries required by the official Linux Qt binaries |

Removing a runtime image plugin changes
`QImageReader::supportedImageFormats()` and therefore changes the Extensions
menu and its tests. A thinner Qt installation is not equivalent to the verified
toolchain.

## Install Qt 6.12.0 locally

[`aqtinstall`](https://github.com/miurahr/aqtinstall) downloads the official Qt
binary archives and patches their installation paths. Version 3.3.0 was used
for the migration.

Choose a persistent output directory outside the repository. The example below
installs Qt below `/home/mpetrick/Qt`:

```bash
mkdir -p /tmp/cullendula-qt-install
cd /tmp/cullendula-qt-install

pipx run --spec aqtinstall==3.3.0 aqt install-qt \
  linux desktop 6.12.0 linux_gcc_64 \
  --outputdir /home/mpetrick/Qt \
  --archives qtbase qttools qtdeclarative qtsvg qttranslations icu \
  --modules qtimageformats
```

Running the installer outside the repository matters because `aqtinstall`
writes `aqtinstall.log` into its current working directory.

For a disposable verification run, use an output directory under `/tmp`
instead. The original migration used:

```text
/tmp/cullendula-qt-6.12.0-aqt/6.12.0/gcc_64
```

Files under `/tmp` can disappear after cleanup or reboot and should not be used
as a permanent development installation.

## Verify the installation

Set a project-specific variable to the Qt kit directory created by the
installer:

```bash
qt_root=/home/mpetrick/Qt/6.12.0/gcc_64

"$qt_root/bin/qtpaths6" --qt-version
"$qt_root/bin/lrelease" -version
test -f "$qt_root/lib/cmake/Qt6/Qt6Config.cmake"
test -f "$qt_root/plugins/imageformats/libqwebp.so"
```

Both version commands must report `6.12.0`. The CMake package and WebP plugin
checks prove that the development files and the required runtime image formats
are present.

## Build and run the full local gate

CMake caches the path of the previously selected Qt installation. Remove only
the generated build directories before switching minor Qt versions:

```bash
cmake -E remove_directory build
cmake -E remove_directory build-coverage
```

Run the canonical pipeline with Qt 6.12.0 at the front of every relevant search
path:

```bash
qt_root=/home/mpetrick/Qt/6.12.0/gcc_64

env -u DISPLAY -u WAYLAND_DISPLAY \
  PATH="$qt_root/bin:$PATH" \
  CMAKE_PREFIX_PATH="$qt_root" \
  QT_ROOT_DIR="$qt_root" \
  LD_LIBRARY_PATH="$qt_root/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
  ./localPipeline.sh --noRun
```

Unsetting the display variables merely prevents generated HTML reports from
being opened during a non-interactive verification run. It does not skip a
mandatory stage.

For a direct application smoke test after the pipeline:

```bash
qt_root=/home/mpetrick/Qt/6.12.0/gcc_64

LD_LIBRARY_PATH="$qt_root/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
QT_QPA_PLATFORM=offscreen \
CULLENDULA_EXIT_AFTER_STARTUP_MS=0 \
./build/src/Cullendula
```

## Repository changes required for the port

The Qt version is deliberately repeated where the build and hosted platforms
must install the same exact release. A minor-version port is incomplete until
all of the following agree:

1. Change `CULLENDULA_EXPECTED_QT_VERSION` in `CMakeLists.txt`.
2. Change the matching environment value and visible job names in
   `.github/workflows/ci.yml`.
3. Change the matching environment value in `.github/workflows/release.yml`.
4. Update Windows repository paths and package identifiers. Qt 6.12.0 uses
   `qt6_6120`, `qt6_6120_msvc2022_64`, and `qt.qt6.6120.*`.
5. Update the Qt badge, dependency example, and dependency table in `README.md`.
6. Update the exact pin documented in `AGENTS.md`.
7. Bump the Cullendula patch version in `CMakeLists.txt`, `README.md`,
   `CHANGELOG.md`, and the three assertions in
   `slot_Test_VersionMetadata_IsDocumentedConsistently()`.
8. Validate every Linux and Windows archive URL used by CI and packaging.
9. Run the full local pipeline with the new Qt installation.
10. Push a review branch, open a linked pull request, and require both Linux and
    Windows GitHub Actions jobs to pass before merging.

No C++ compatibility changes were needed for the 6.11.2 to 6.12.0 migration.
The effective code change was an exact toolchain-pin and package-repository
update, but the build, tests, packaging inputs, documentation, and release
metadata all had to be verified together.

## Windows archive layout

The Windows workflow downloads official archives directly. `aqtinstall` 3.3.0
looks for an `Updates.xml` path that Qt does not publish for this layout, while
the real packages are inside the architecture-suffixed directory:

```text
https://download.qt.io/online/qtsdkrepository/windows_x86/desktop/
  qt6_6120/
    qt6_6120_msvc2022_64/
      qt.qt6.6120.win64_msvc2022_64/
      qt.qt6.6120.addons.qtimageformats.win64_msvc2022_64/
```

The PowerShell steps in both workflows read those directory listings, select
the non-debug archive for each required component, extract the archives, and
verify that `Qt6Config.cmake` exists. Keep the CI and release implementations in
sync when moving to another Qt release.

## Evidence from this migration

The Qt 6.12.0 migration produced the following verification results:

- normal and coverage configurations compiled successfully;
- the application started and exited cleanly with the offscreen platform;
- all QtTest tests passed;
- line coverage remained 98.6%, above the 95% gate;
- Doxygen completed with an empty warnings file;
- Cppcheck completed without findings;
- clang-format changed no tracked source file;
- GitHub Actions passed on Linux and Windows;
- the Linux AppImage and Windows zip passed their isolated package startup tests.

The release and workflow links belong in the relevant GitHub issues and pull
request so that this reusable procedure remains independent of one run number.
